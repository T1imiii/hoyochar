В связи с этим, разработка веб-приложения-базы данных «HoYoChar» становится важной задачей, позволяющей оптимизировать доступ к информации, управлять большим объемом данных о персонажах и улучшать пользовательский опыт для фанатов.

Практическое значение данной работы заключается в том, что созданное веб-приложение будет служить инструментом для повышения вовлеченности и осведомленности игрового сообщества. Гипотеза исследования заключается в том, что внедрение централизованного интерактивного веб-приложения позволит значительно улучшить пользовательский опыт для фанатов игр HoYoverse, оптимизируя процессы поиска и изучения информации и способствуя формированию более осведомленного сообщества.

**1. Основная часть**

**1.1. Теоретическая часть**

**1.1.1. Анализ предметной области: феномен игр HoYoverse**

Компания HoYoverse (ранее miHoYo) стала мировым феноменом в игровой индустрии благодаря своим высококачественным играм с глубоким сюжетом, яркими персонажами и уникальным визуальным стилем. Проекты, такие как Genshin Impact, Honkai: Star Rail и грядущий Zenless Zone Zero, привлекают миллионы игроков по всему миру.

Ключевой особенностью этих игр является наличие огромного количества игровых персонажей, каждый из которых обладает своей уникальной историей, дизайном, способностями и связями с другими персонажами. Это создает обширные и сложные вселенные, которые фанаты с удовольствием исследуют. Обилие контента порождает высокий спрос на структурированную и легкодоступную информацию. Игроки постоянно ищут данные о персонажах, гайды, новости, а также сопутствующий контент, такой как официальная музыка и арт.

**1.1.2. Обзор существующих решений и информационных ресурсов**

На данный момент существует множество ресурсов, созданных фанатским сообществом для удовлетворения информационных потребностей игроков:

*   **Вики-энциклопедии (Fandom, etc.):** Это наиболее популярный формат. Они содержат огромное количество информации, но часто перегружены текстом, имеют устаревший дизайн и могут быть сложны для навигации, особенно для новых игроков.
*   **Сайты-базы данных:** Ресурсы вроде Honey Hunter World, которые фокусируются на "утечках" и детальных характеристиках персонажей, но их интерфейс часто недружелюбен и ориентирован на хардкорных игроков.
*   **Интерактивные карты:** Специализированные сайты для отслеживания ресурсов в игровом мире.

Несмотря на обилие ресурсов, отсутствует единое, стильное и удобное приложение, которое бы объединяло информацию о персонажах из всех основных игр HoYoverse и предоставляло бы сопутствующий контент, такой как музыкальный плеер, в едином интерфейсе. Данный проект нацелен на то, чтобы занять эту нишу.

**1.1.3. Обоснование выбора технологий для разработки**

Для реализации данного проекта был выбран стек технологий, ориентированный на создание современного, быстрого и легко поддерживаемого веб-приложения без использования тяжелых фреймворков.

**1.1.3.1. HTML5 и его семантические возможности**

HTML5 является стандартом для создания веб-страниц. Использование семантических тегов, таких как `<header>`, `<main>`, `<nav>`, `<section>`, `<article>`, позволяет создать логичную и понятную структуру документа. Это не только улучшает читаемость кода для разработчиков, но и положительно сказывается на доступности (a11y) для людей, использующих скринридеры, а также на поисковой оптимизации (SEO).

**1.1.3.2. CSS3: Стилизация и адаптивный дизайн**

CSS3 предоставляет мощные инструменты для визуального оформления приложения. В проекте активно используются:
*   **Flexbox и Grid Layout:** для создания гибких и сложных сеток расположения элементов, что является основой адаптивного дизайна.
*   **CSS Variables (Custom Properties):** для определения цветовой палитры и других констант, что упрощает смену темы и поддержку кода.
*   **Transitions и Animations:** для создания плавных и приятных для глаза микро-взаимодействий, таких как появление карточек персонажей или смена состояния кнопок.
*   **Media Queries:** для адаптации интерфейса под различные размеры экранов — от мобильных телефонов до широкоформатных мониторов.

**1.1.3.3. JavaScript (ES6+): Язык для создания интерактивности**

Современный JavaScript (стандарт ECMAScript 2015 и выше) является ядром интерактивности приложения. Ключевые возможности, использованные в проекте:
*   **Fetch API и Promises:** для асинхронной загрузки данных из JSON-файлов без перезагрузки страницы.
*   **Arrow Functions, Destructuring, Spread/Rest Operators:** для написания более чистого, короткого и читаемого кода.
*   **DOM Manipulation:** для динамического создания, изменения и удаления HTML-элементов, что позволяет отображать персонажей, обновлять плеер и т.д.
*   **Event Listeners:** для обработки действий пользователя, таких как клики, ввод текста в поле поиска, изменение громкости.

**1.1.3.4. JSON как формат хранения данных**

JavaScript Object Notation (JSON) был выбран в качестве простого и легковесного формата для хранения данных о персонажах и музыке. Его преимущества:
*   **Человекочитаемость:** Структура JSON легко понятна человеку.
*   **Простота парсинга:** JavaScript имеет встроенные методы (`JSON.parse()`) для преобразования JSON-строки в объект, что делает работу с данными тривиальной.
*   **Гибкость:** Позволяет легко изменять и расширять структуру данных без необходимости миграции сложной базы данных.

Для данного курсового проекта использование локальных JSON-файлов является оптимальным решением, имитирующим работу с API и позволяющим сосредоточиться на логике фронтенда.

**1.2. Практическая часть**

**1.2.1. Проектирование архитектуры веб-приложения**

Приложение спроектировано как **Single Page Application (SPA)**. Это означает, что пользователь загружает одну HTML-страницу (`index.html`), а все последующие переходы между разделами (например, с Genshin Impact на Honkai: Star Rail) и обновления контента происходят динамически с помощью JavaScript, без полной перезагрузки страницы.

**Структура файлов проекта:**
*   `index.html`: Основная и единственная HTML-страница, содержащая базовую разметку и контейнеры для динамического контента.
*   `style.css`: Основной файл стилей для общего оформления сайта.
*   `music.css`: Стили, специфичные для музыкального плеера.
*   `main.js`: Основной скрипт, отвечающий за логику отображения персонажей, навигацию, поиск.
*   `music.js`: Скрипт, управляющий функциональностью музыкального плеера.
*   `characters.json`, `honkai_star_rail.json`, `zenless_zone_zero.json`: Файлы с данными о персонажах для каждой игры.
*   `music.json`: Файл с данными о музыкальных треках.
*   `images/`: Папка с изображениями (логотипы, иконки, фоны, изображения персонажей).
*   `music/`: Папка с аудиофайлами.

**1.2.2. Разработка структуры данных**

Данные о персонажах хранятся в JSON-файлах с одинаковой структурой для каждой игры, что обеспечивает унифицированный подход к их обработке.

Пример структуры объекта персонажа в `characters.json`:
```json
{
  "name": "Albedo",
  "mainImage": "images/genshinImpact/mainImages/albedo_main.webp",
  "sideImage": "images/genshinImpact/sideImages/albedo_side.webp"
}
```

Аналогично, данные для музыкального плеера в `music.json` имеют следующую структуру:
```json
{
  "title": "WHITE NIGHT",
  "artist": "Jake Miller",
  "image": "music/music_images/WHITE NIGHT.jpg",
  "path": "music/Jake Miller - WHITE NIGHT.mp3"
}
```
Такая структура позволяет легко расширять данные, добавляя новые поля (например, описание персонажа, его редкость, элемент и т.д.) без изменения основного кода.

**1.2.3. Реализация пользовательского интерфейса (UI)**

**1.2.3.1. Главная страница и навигация**

Интерфейс спроектирован с упором на минимализм и визуальную привлекательность.
*   **Шапка сайта (`header`):** Содержит логотип приложения "HoYoChar" и основную навигацию.
*   **Навигация:** Реализована в виде вкладок с логотипами игр (Genshin Impact, Honkai: Star Rail, Zenless Zone Zero), а также ссылок на разделы "Персонажи", "Музыка", "Новости". Активная вкладка подсвечивается, давая пользователю понять, в каком разделе он находится.
*   **Основной контент (`main`):** Центральная область, где динамически отображается выбранный контент — сетка с персонажами или интерфейс музыкального плеера.

**1.2.3.2. Секция отображения персонажей**

Это ключевая часть приложения.
*   **Карточка персонажа:** Каждый персонаж представлен в виде "карточки". При наведении курсора на карточку, основное изображение персонажа плавно сменяется на альтернативное, создавая приятный интерактивный эффект. Это реализовано с помощью CSS Transitions и изменения `opacity`.
*   **Сетка:** Карточки персонажей выстраиваются в адаптивную сетку с помощью CSS Grid. Количество колонок в сетке автоматически подстраивается под ширину экрана, обеспечивая оптимальное отображение на любых устройствах.
*   **Поле поиска:** Над сеткой персонажей расположено поле ввода (`<input type="search">`), позволяющее пользователю в реальном времени фильтровать персонажей по имени.

**1.2.3.3. Музыкальный плеер**

Интерфейс музыкального плеера включает все стандартные элементы управления:
*   Обложка текущего трека.
*   Название песни и исполнитель.
*   Кнопки управления: "Предыдущий трек", "Воспроизведение/Пауза", "Следующий трек".
*   Прогресс-бар, который визуализирует текущую позицию воспроизведения и позволяет перематывать трек.
*   Регулятор громкости.

**1.2.4. Реализация программной логики**

**1.2.4.1. Загрузка и обработка данных персонажей (`main.js`)**

Основная функция `loadCharacters(gameFile)` отвечает за загрузку и отображение персонажей.
1.  С помощью `fetch(gameFile)` отправляется запрос на получение соответствующего JSON-файла.
2.  Метод `.then(response => response.json())` парсит полученный ответ в JavaScript-объект.
3.  Далее, в цикле (`forEach`) для каждого объекта-персонажа в массиве данных создается HTML-разметка для его карточки. Разметка создается как строка и затем вставляется в DOM с помощью `innerHTML`, что является эффективным способом для генерации большого количества элементов.
4.  На каждую созданную карточку навешиваются обработчики событий `mouseenter` и `mouseleave` для реализации эффекта смены изображений.

**1.2.4.2. Реализация функции поиска и фильтрации (`main.js`)**

1.  На поле поиска установлен обработчик события `input`.
2.  При каждом вводе символа, функция получает текущее значение из поля, приводит его к нижнему регистру для регистронезависимого поиска.
3.  Затем она перебирает все карточки персонажей на странице.
4.  Для каждой карточки извлекается имя персонажа, также приводится к нижнему регистру.
5.  Если имя персонажа включает в себя поисковый запрос (`includes()`), карточке устанавливается стиль `display: 'block'`, иначе — `display: 'none'`. Это позволяет мгновенно скрыть неподходящие карточки.

**1.2.4.3. Управление музыкальным плеером (`music.js`)**

Логика плеера инкапсулирована в файле `music.js`.
1.  **Загрузка плейлиста:** При переходе в раздел "Музыка", скрипт загружает `music.json` и на его основе динамически создает плейлист в интерфейсе.
2.  **Управление воспроизведением:**
    *   Создается объект `new Audio()`.
    *   Функции `playSong()` и `pauseSong()` управляют методами `audio.play()` и `audio.pause()`, а также меняют иконку на кнопке.
    *   Функции `nextSong()` и `prevSong()` отвечают за переключение треков, циклически изменяя индекс текущей песни в плейлисте.
3.  **Обновление интерфейса:**
    *   В процессе воспроизведения трека, событие `timeupdate` на аудио-объекте используется для обновления прогресс-бара.
    *   Событие `ended` используется для автоматического переключения на следующий трек.
    *   Клик по прогресс-бару позволяет рассчитать новую позицию и установить ее в `audio.currentTime` для перемотки.

**1.2.5. Тестирование и отладка**

Тестирование проводилось вручную на разных этапах разработки:
*   **Кроссбраузерное тестирование:** Проверка корректной работы и отображения в последних версиях браузеров Google Chrome и Mozilla Firefox.
*   **Тестирование адаптивности:** Изменение размеров окна браузера и использование инструментов разработчика для эмуляции различных устройств (смартфоны, планшеты).
*   **Функциональное тестирование:** Проверка всех интерактивных элементов: работа навигации, корректность загрузки данных, правильность работы поиска, функциональность всех кнопок музыкального плеера.
*   **Отладка:** В процессе разработки активно использовались `console.log()` для вывода промежуточных значений и состояний, а также вкладка "Network" в инструментах разработчика для контроля за загрузкой файлов.

**2. Заключение**

В ходе выполнения данной курсовой работы была достигнута поставленная цель: разработано эффективное интерактивное веб-приложение-справочник «HoYoChar» для фанатов игр компании HoYoverse.

В рамках работы были решены следующие задачи:
1.  Проведен анализ предметной области и потребностей целевой аудитории, что подтвердило актуальность создания подобного ресурса.
2.  Спроектирована архитектура одностраничного приложения (SPA) и гибкая структура данных на основе JSON-файлов.
3.  Реализован современный, интуитивно понятный и адаптивный пользовательский интерфейс с использованием HTML5 и CSS3.
4.  Разработана программная логика на чистом JavaScript (ES6+), реализующая ключевые функции: динамическую загрузку контента, поиск в реальном времени и полнофункциональный музыкальный плеер.

Разработанное приложение успешно решает проблему разрозненности информации, предоставляя пользователям единую точку доступа к данным о персонажах и музыкальному контенту из популярных игр HoYoverse. Гипотеза исследования о том, что внедрение такого приложения улучшит пользовательский опыт, подтвердилась: приложение предлагает более современный и удобный интерфейс по сравнению со многими существующими фанатскими ресурсами.

**Пути дальнейшего развития проекта:**
*   **Расширение базы данных:** Добавление более подробной информации о персонажах (биография, способности, характеристики), а также новых игр.
*   **Переход на полноценный бэкенд:** Создание серверной части (например, с помощью Node.js/Express) и базы данных (например, MongoDB или PostgreSQL) для более надежного хранения данных и реализации нового функционала.
*   **Пользовательские аккаунты:** Внедрение системы регистрации и авторизации, что позволит пользователям создавать собственные коллекции любимых персонажей или плейлисты.
*   **Интеграция с API:** Если HoYoverse предоставит публичный API, можно будет автоматизировать обновление данных в приложении.

Данная курсовая работа демонстрирует владение современными технологиями веб-разработки и умение применять их для решения практических задач, создавая полезный и качественный продукт.
